\section*{2. Purpose and scope}

Le SDP definit les processus de developpement logiciel du dispositif medical en conformite avec IEC~62304, SOP-025 et SOP-027.

\subsection*{2.1 Scope}
Le plan couvre : firmware, controle embarque, applications et composants SOUP.

Le document est revu a chaque Gate Review (G1 a G4) et mis a jour sous change control.

\section*{3. Software safety classification}

\textbf{Classification preliminaire :} Class C (hypothese conservative pour dispositif actif).

\textbf{Strategie de segregation :}
\begin{itemize}
  \item Boucles de controle critiques traitees en Class C.
  \item Applications auxiliaires potentiellement Class B/A si segregation architecturale demontree.
\end{itemize}

\section*{6. Traceability and verification framework}

\textbf{Traceability rules :}
\begin{itemize}
  \item Requirement logicielle : lien amont vers exigence systeme et/ou mesure de maitrise du risque.
  \item Requirement logicielle : lien aval vers design, code et activite de verification.
  \item Revue de completude avant chaque gate.
\end{itemize}

\textbf{Verification strategy (synthese) :}
\begin{tabularx}{\textwidth}{|p{1.2cm}|p{3.1cm}|X|}
\hline
\textbf{Gate} & \textbf{Verification activity} & \textbf{Acceptance criteria} \\
\hline
G1 & Design review & Exigences et architecture baselined, coherence et traceabilite verifiees \\
\hline
G2 & Unit verification & Static analysis conforme, code review approuvee, unit tests passants \\
\hline
G3 & Integration \& system verification & Couverture exigences et tests integration/system valides, regression maitrissee \\
\hline
G4 & Release verification & Package de release complet, anomalies critiques resolues ou justifiees \\
\hline
\end{tabularx}

\section*{7. Software configuration management (SCM)}

SCM aligne sur SOP-027 avec strategie multi-repo et branching controle.

\begin{itemize}
  \item \texttt{main}: baseline de release, commits directs interdits.
  \item \texttt{develop}: integration continue des evolutions.
  \item \texttt{release}: preparation de version officielle.
  \item \texttt{hotfix}: correction post-release avec impact analysis.
  \item \texttt{feature}/\texttt{bugfix}: branches de developpement.
\end{itemize}

\section*{8. SOUP, cybersecurity, release and maintenance}

\textbf{SOUP management :}
\begin{itemize}
  \item Liste SOUP maintenue et revue periodiquement.
  \item Verification des composants SOUP dans les plans de test.
  \item Surveillance des vulnerabilites et des fins de vie.
\end{itemize}

\textbf{Release :}
la release inclut version, hash, anomalies residuelles, composants SOUP et environnement de build, puis archivage controle.

\textbf{Problem resolution et maintenance :}
toute anomalie suit un cycle log, triage, investigation, resolution, regression, puis traceabilite vers commit et enregistrement qualite.
